# Dependency license and distribution review

**Snapshot:** 2026-11-23. **Project:** `Ali7488/pdf-manager`. **Licensing baseline:** original project files under MIT; the combined distributed application under GNU AGPL-3.0 because it contains PyMuPDF/MuPDF. This is a technical compliance record, not a legal opinion.

## Scope and method

This inventory reconciles the tracked `licenses/manifest.json`, `uv.lock`, `frontend/package-lock.json`, the third-party notices, the Windows build configuration and the installed-bundle inventory check. The project contains **55 separately recorded components**: 18 python, 9 frontend, 21 mupdf, 7 other. An entry describes the component's declared or transitive role, **not proof that every code path in its package executes**. The exact license text shipped is linked in the final column; the upstream link gives a publisher-maintained project, package or license page.

The Windows executable built in CI uses the Windows-specific entries. Python/Qt entries labeled Linux describe **run-from-source dependencies and future packages**, not a verified Linux redistributable. MuPDF component claims follow its 1.28.2 source archive, which was used to collect the notices. A third-party module's inclusion in the MuPDF source tree does not by itself prove its binary code is linked into every wheel. The installer also provides separate optional-program installation, which is distinguished below.

## Windows release gates

1. **Unresolved: Microsoft SDK binaries and AGPL Corresponding Source.** pywebview 6.2.1 includes five WebView2 SDK DLLs matching Microsoft.Web.WebView2 1.0.3856.49. Their NuGet license grants BSD-like binary redistribution with notices; these texts are included in the installed license tree. This **does not by itself establish** that the complete-source obligation of the combined AGPL application is met. The system-library exception requires a separate interpretation. Microsoft confirms the managed app must ship SDK assemblies and loaders. References: [SDK package](https://www.nuget.org/packages/Microsoft.Web.WebView2/1.0.3856.49), [Microsoft distribution documentation](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution), [AGPL-3.0 terms](https://www.gnu.org/licenses/agpl-3.0.en.html).
2. **Unresolved: Microsoft Visual C++ runtime.** The Windows binary includes vcruntime/MSVCP DLLs. Microsoft restricts redistribution to licensed Visual Studio users under its terms; the [GNU GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html) specifically warns that bundling these DLLs affects System Libraries treatment. The repository already excludes unneeded Universal C Runtime/MFC files. Determine an approved runtime distribution strategy before public release. References: [Microsoft licensing](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files) and [central deployment guidance](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist/).
3. **Unresolved: asset provenance.** The original application icon and its preview do not have documented authorship/redistribution rights. An original author confirmation or replacement is necessary; the Feather-derived settings glyph and Open Sans font already have licenses.
4. **Unfinished release:** source artifacts are generated by CI and the Windows installer smoke test passed on a runner, but no release is published and no real Windows PC acceptance run is recorded. Source and installer must be from the **same immutable release revision**, with downloads and checksums accessible to recipients.
5. **Source integrity qualification:** most Python source archives are verified against `uv.lock`, npm archives against `package-lock.json`, MuPDF/PyInstaller against pinned hashes and CPython 3.13.17 against the SHA-256 published on [Python.org](https://www.python.org/downloads/release/python-31317/). The pywin32 GitHub b312 archive has no pinned upstream digest in the source manifest. The generated `SHA256SUMS` detects later changes to the downloaded archive, but does not establish independent publisher authenticity for that file.

## Linux package gate

PySide6 and Qt WebEngine are Linux-only in this app. Qt's [LGPL obligations](https://www.qt.io/development/open-source-lgpl-obligations) include source availability under the distributor's control, appropriate notices, and user ability to replace/relink the LGPL libraries. [Qt WebEngine licensing](https://doc.qt.io/qtforpython-6.11/overviews/qtwebengine-licensing.html) additionally requires the Chromium/third-party notices; these are **not yet an audited Linux package**. Do not carry forward a Windows installer sign-off to the planned Linux v0.75 release.

## Automated checks and limits

`scripts/check_licenses.py repo` checks resolved production dependencies, pinned versions, presence of license texts, AGPL notices, and unique manifest paths. `scripts/check_licenses.py bundle ... --installed` checks native files and byte-exact installed notices. The source collector verifies the pinned CPython archive digest; it still cannot authenticate the unpinned pywin32 upstream archive or resolve the legal Microsoft exception question.

The Windows installer and source collection workflow previously completed on the same revision at [Actions run 45202300026](https://github.com/Ali7488/pdf-manager/actions/runs/45202300026). It was a Windows **virtual machine**, not a real-user acceptance test. Changes after that run require CI and packaging checks again.
